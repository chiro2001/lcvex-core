## 目标与背景

- 此前 T-101/T-090 已确认 `A64_FP_SIMD=0` 只改变 ID 寄存器报告，
  **并不会真正省略 `lcvex_fp_scalar` / `lcvex_neon_fp` / `lcvex_neon_int` 实例**。
- 本任务要实现“真 generate-gate”实验开关：当 `A64_FP_SIMD=0` 时，
  RTL 完全不例化/展开这三个 FP/NEON 执行单元；默认值保持 FP/NEON 开启，
  不改变现有单核/双核功能。
- 本地仅做 Verilator lint/build/smoke 验证；不启动 Quartus full flow，
  不读 license，不修改远端原始 QSF/SDC。

## 调查结论：当前 gating 路径

| 层次 | 现状 |
| --- | --- |
| `lcvex_decode` | 已有 `A64_FP_SIMD` 参数，且只用于 MRS ID/MVFR 寄存器返回无 FP 值；不会禁止 decode 到 FP/NEON 指令。 |
| `lcvex_core` | 原有 `A64_FP_SIMD` 参数透传给 decode，但 `lcvex_fp_scalar`、`lcvex_neon_int`、`lcvex_neon_fp` 三个实例无条件存在于 EX 级。 |
| `lcvex_neon_fp` | 内部又 generate 4 个 `lcvex_fp_scalar` lane，因此只关 scalar 顶层并不能移走最大 FP 热点。 |
| `lcvex_catapult_soc_top` | 已有 `A64_FP_SIMD` 参数并向 core 透传。 |
| `lcvex_core_wrap` / `lcvex_cluster_top` | 原先硬编码 `A64_FP_SIMD=1'b1`，未暴露 no-FP 参数。 |
| `fpga/catapult_a10/rtl/lcvex_catapult_a10_top.sv` | 原先硬编码 `A64_FP_SIMD=1'b1`。 |
| `lcvex_fp_state` | 保留 V0-V31、FPCR/FPSR、CPACR 状态；本实验未移除，作为下一档面积缩减候选。 |

## 实现

1. **`rtl/lcvex_core.sv`**
   - 将 `lcvex_fp_scalar`、`lcvex_neon_int`、`lcvex_neon_fp` 三个实例包进
     `generate if (A64_FP_SIMD) ... else ... endgenerate`。
   - `A64_FP_SIMD=0` 分支用常量驱动原实例的输出：
     `fp_ex_result/int_result/flags/nzcv`、`fp_div_busy/done`、
     `neon_ex_wdata`、`neon_fp_ex_wdata/fpsr_flags`。
   - 这样 Verilator/Quartus elaboration 中不会存在 FP/NEON 执行单元层次；
     纯 scalar core 可正常 lint/build。

2. **参数透传（默认值均保持 1，不改变默认行为）**
   - `rtl/lcvex_core_wrap.sv`：新增 `parameter logic A64_FP_SIMD = 1'b1`，
     传入内部 `lcvex_core`。
   - `rtl/lcvex_cluster_top.sv`：新增 `parameter logic A64_FP_SIMD = 1'b1`，
     传给每个 `lcvex_core_wrap`。
   - `fpga/catapult_a10/rtl/lcvex_catapult_a10_top.sv`：新增
     `parameter logic A64_FP_SIMD = 1'b1`，传给 `lcvex_catapult_soc_top`。
   - `fpga/catapult_a10/tb/sv/lcvex_catapult_soc_tb.sv`：参数化
     `A64_FP_SIMD`，使 SoC smoke 可直接用 `-GA64_FP_SIMD=0` 构建/运行。

## 面积/类型影响

本机没有 Quartus，无法给出真实 A10 LC/RAM/DSP/时序。
Verilator elaboration 作为可复现代理指标：

- core：elaborated C++ 体积约 **41.7 MB -> 2.9 MB**（-93%），C++ 文件数 19 -> 6。
- Catapult SoC：elaborated C++ 体积约 **45.0 MB -> 5.6 MB**（-88%），C++ 文件数 21 -> 9。
- cluster（CORE_COUNT=1）：**45.1 MB -> 4.4 MB**（-90%），C++ 文件数 19 -> 6。
- 量化时间从 23-25s 降到 0.7-1.3s（Verilator 前端 elaboration）。
- 这些数据只说明“FP/NEON 执行单元从设计层次中被移除”；真实 Quartus LC/RAM
  缩减和是否足够避免 75GB OOM 仍需 FPGA-F 在远端跑缩减 synthesis，本地不能替代。

## 边界与风险

1. **`A64_FP_SIMD=0` 下不再实现 FP/NEON 指令语义**。执行单元被移除后，
   若软件仍执行 FP/NEON，结果将来自常量/未定义路径。实验分支明确注释不承诺；
   若要把 no-FP 作为正式配置，应补充“执行 FP/NEON -> UDEF/FP trap”的 decode 门控和测试。
2. **`lcvex_fp_state` 及 V0-V31/FPCR/FPSR/CPACR 仍保留**，所以还不是最大面积缩减。
   后续可在 FPGA-F/后续任务中再加第二档 generate-gate，但会涉及核心端口与
   checkpoint/commit 路径，需要更完整的 no-FP 架构裁剪。
3. **未做 Quartus**：无法给出 LC/ALM/RAM/DSP/Fmax/STA，无法确认 Synthesis OOM 消除。
4. **未启动完整 B5 full flow**；未修改远端原始 QSF/SDC；未读 license；未引入 SVE。
5. **默认单核/双核路径未变**：所有新参数默认 `1'b1`，默认实例化与之前一致。

## 建议

**建议合入**：该改动在默认参数下是纯增量基础设施，默认功能不变；它提供了后续
FPGA-F 真正可用的 no-FP 开关。合入后 FPGA-F 可用 `A64_FP_SIMD=0` 在远端跑缩减
Synthesis。但若决定把 no-FP 作为正式软件可见配置，还需补 FP/NEON 指令的
trap/UDEF 语义验证；本任务未声称完成该功能语义。
