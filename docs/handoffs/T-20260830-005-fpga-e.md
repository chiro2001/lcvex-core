## 结论

1. **Quartus Prime Pro 21.4 的 QSF 分区语法已确认**：不是旧 `PARTITION_NAME`，
   而是：
   ```text
   set_instance_assignment -name PARTITION <partition_name> -to "<instance_path>"
   ```
   **不能带 `-section_id`**；`PARTITION_NAME`、`PARTITION_NETLIST_TYPE`、
   `DESIGN_PARTITION_NAME` 等在 QSF 中报错/被忽略。
2. **单工程只加 `PARTITION` 后，`quartus_syn` 会把设计先整体 Analysis &
   Elaboration，再按 partition 依次 synthesize**。若 70GB OOM 发生在
   elaboration（T-101 `soc_only` 日志停留在 `Elaborating from top-level entity`
   之后、未出现 `There are N partitions`/`Synthesizing partition`），
   这种“单工程 partition”**不能保证降低峰值**。
3. **真正能降低首轮 synthesis 峰值的路线是 block-based bottom-up**：
   - 每个大分区（core、L1D、L2WB、SoC/coh、AXI/EMIF adapter）作为独立工程
     standalone synthesis；
   - `quartus_cdb --export_partition ... --snapshot synthesized --file <block>.qdb`
     导出 QDB；
   - 顶层工程用 black-box/imported partition 组装。
4. 远端已成功验证：
   - 小工程 partition 语法、2 个 partition 的完整 `quartus_syn`；
   - `quartus_cdb --export_partition` / `--import_partition` 命令可用；
   - **未验证“import 后顶层 synthesis 跳过该 partition 重新综合”**——简单
     `quartus_syn` 在 import 后仍重新综合 black box，说明真正的组装流程还需要
     `PARTITION_PRESERVE`/post-synthesis import/fitter flow 的进一步确认。
5. **不建议在未完成上述 bottom-up 验证前重启 B5 full flow**。

## 推荐命令

### Tier 1：单工程 partition（成本最低，先试）

```powershell
# 在远端 build/T-20260830-005/partitioned_soc 下创建实验 QSF/QPF，
# 引用当前 RTL（或远端已同步的最新 RTL）并追加上述 PARTITION assignments
cd D:\Projects\fpga-altra\lcvex\build\T-20260830-005\partitioned_soc
D:\Software\intelFPGA_pro\21.4\quartus\bin64\quartus_syn.exe --read_settings_files=on --write_settings_files=off partitioned_soc -c partitioned_soc
```

只跑 synthesis，不启动完整 `quartus_sh --flow compile`（即不跑到 fitter/asm/STA）。

### Tier 2：Standalone + QDB bottom-up（推荐用于真正降峰值）

1. 为每个大分区建独立工程，只有该模块/ wrapper 为 TOP。先跑：
   ```powershell
   D:\Software\intelFPGA_pro\21.4\quartus\bin64\quartus_syn.exe --read_settings_files=on --write_settings_files=off <block> -c <block>
   ```
2. 导出该分区的 synthesized snapshot：
   ```powershell
   D:\Software\intelFPGA_pro\21.4\quartus\bin64\quartus_cdb.exe <block> -c <block> --export_partition root_partition --snapshot synthesized --file <block>.qdb
   ```
3. 在顶层实验工程中导入：
   ```powershell
   D:\Software\intelFPGA_pro\21.4\quartus\bin64\quartus_cdb.exe <top> -c <rev> --import_partition <partition> --file <block>.qdb
   ```
4. 验证顶层不会对已导入 partition 重新做 RTL synthesis。若 `quartus_syn`
   仍重综合，需要查找 `PARTITION_PRESERVE`/post-synthesis import 流程，
   或改用 `quartus_sh --flow compile` 在 fitter 阶段使用 imported QDB。
5. 全部通过后才允许进入 B5 full flow（fit/STA/SOF）。

### QDB incremental/recompile

- `quartus_sh --flow recompile <top> -c <rev>` 可用于增量重编译；
- `quartus_sh --flow compile <top> -c <rev> -start synthesis -end synthesis`
  可只跑到 synthesis；
- 本任务未运行 B5 级 QDB 增量，未宣称收益。

## 预期收益与风险

| 方案 | 预期内存 | 预期时间 | 主要风险 |
| --- | --- | --- | --- |
| 只加单工程 PARTITION | 若 OOM 在 per-partition synthesis：可能下降；若在 elaboration：无改善甚至更高 | 额外 partition 处理开销，总时间可能略增 | T-101 日志表明当前 OOM 更像 elaboration 早期；不能依赖 |
| Standalone + QDB bottom-up | 每个独立 synthesis 只处理一个分区；理论峰值约等于最大独立分区内存（L2/L1D/core） | 多工程多次综合 + export/import/assembly；总墙钟可能大于单次 | QDB 版本/接口兼容、跨分区时序、顶层 black-box 接口、流程复杂；尚未验证 import 后不重综合 |
| no-FP（FPGA-D）+ 减小 L2（FPGA-B）+ 多周期除法（FPGA-C） | 大幅缩小 core/FP 和 cache 数据阵列 | 可能显著降低 synthesis 时间 | no-FP 不是正式功能配置；需为软件提供 FP/NEON trap/UDEF |

基于已有 standalone 数据：
- `lcvex_l1_d_wb`：182,885 LC，约 3.64 GB VM，4m24s
- `lcvex_l2_wb`：>37min 未完成，QDB 约 190MB —— 最大热点
- `lcvex_axi4_avalon_adapter`：22,381 LC，935 MB，56s
- `soc_coh`：10min 超时（T-001 未完成）
- `A64_FP_SIMD=0` 在 Verilator 的 elaboration 指标下降约 88-93%
