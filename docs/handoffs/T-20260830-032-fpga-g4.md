## 结论

1. **真实 SoC 路径已放回，未使用 stub**：实验工程包含 `lcvex_catapult_a10_top` -> `lcvex_catapult_soc_top` -> 真实 `lcvex_core` / coherent / AXI / L1/L2 / EMIF adapter / BRAM boot / JTAG-UART / EPCQ CSR。
2. **显式 M20K BRAM 是本次 synthesis 通过的关键**：
   - 主 RTL `rtl/lcvex_bram_boot.sv` 的 `SYNTHESIS` 路径被实际选中（实验 QSF 增加 `VERILOG_MACRO "SYNTHESIS"`）；
   - Quartus synthesis report 明确出现 `soc|bram|u_impl|u_ram` 为 **M20K true dual port**，8192 x 64-bit = 524,288 bits；
   - 合成峰值私有内存 **13,538.9 MB**，工作集 **12,675.5 MB**（监视器），Quartus 报告 Peak VM 13,665 MB；
   - 对比 G3 原真实全综合 45.6GB OOM，本轮已把行为级 BRAM 展开问题从内存热点中移除。
3. **Synthesis PASS，但资源证明 L1D/L2 缓存数据阵列仍以 LUT/ALM 实现**：
   - Synthesis resource summary（root_partition）：估计 ALMs needed **342,341**（A10 约 427,200，约 80%），组合 ALUTs **412,158**，专用寄存器 **143,360**，I/O pin 144，MLAB 0，Block Memory Bits **181,740**，DSP 21，PLL 1；
   - Block Memory Bits 主要来自 EMIF/异步 FIFO/显式 BRAM（M20K 524,288 bits 单独列出），**缓存 data 阵列没有进入 M20K**；
   - 这解释了为什么 fitter 虽然不 OOM 但极慢：超过 34 万 ALM 的 cache 阵列使布局布线压力巨大。
4. **Fitter 未完成**：
   - 已启动 `quartus_sh --flow compile real_a10 -c real_a10 -start fitter -end fitter`，并行 16 核；
   - 运行 **64m21s** 后手动中断，仍无最终 fit report；
   - 监视器峰值私有内存 **15,434 MB**，峰值工作集 **15,179.8 MB**，未触发内存保护；
   - 中断前日志已进入 Fitter placement preparation / register packing（Packed 48 registers into Block RAM, 678 into DSP, 550 register duplicates），但无 fit.summary/fit.rpt；
   - 因此本轮 **没有 fit 资源结论、没有 STA slack/Fmax、没有 assembler/SOF**。
5. **不再需要“原路径副本”或“debug fabric 关闭”**：
   - debug fabric `alt_sld_fab_0` 正常自动生成，合成通过；T-030 的 SDC `-quiet` 改为 `-nowarn` 后也不再卡 periphery placement。

## 为让当前主 RTL 通过 Quartus 21.4 的本地适配（实验已同步到远端隔离工程）

> 注：本次实验期间主线已推进到 `1ab0dfa`，其中已包含 `rtl: apply Quartus 21.4 compatibility rewrites` 提交（8cbe41d/65ce6f6），与本实验早期基于 `f9b26ef` 的本地补丁目标一致；以下列出的是实验隔离工程实际使用的适配点，便于复现。

- `lcvex_decode.sv`：新增 `rdg_low/rdg_bit` 辅助函数，替换 Quartus 不支持的函数调用结果直接部分选择；逻辑立即数变步长循环改为 `case(len)` 展开；NEON immh 部分选择改为临时 `immh` 变量。
- `lcvex_alu.sv`：`bfm_deposit(...)[31:0]`、`clz64/cls64(...)[6:0]` 改为先取完整结果再截取，避免函数调用结果直接 part-select。
- `lcvex_fp_scalar.sv`：删除输入端口 `clk=1'b0`、`rst_n=1'b1` 默认值（Quartus 不接受 input declaration initialization）。
- `lcvex_pkg.sv`：所有 enum literal 宽度改为与 enum 声明宽度严格一致（含 SREG 7-bit、ALU 6-bit 等）。
- `lcvex_core.sv`：LD1R 64-bit lane 复制改为按 size 分支，避免静态展开越界索引。
- `lcvex_l2_wb.sv`：补 `WAYS=1` 的 one-way 命中/替换逻辑（`u_hit1/p_hit1` 在 `WAYS>1` 时才访问 way1）。
- 实验 QSF：添加 `set_global_assignment -name VERILOG_MACRO "SYNTHESIS"`，确保主 BRAM wrapper 选显式 M20K 路径。

这些是当前主 RTL 的 Quartus 兼容性修补，尚未独立提交；后续建议正式合入并配 Verilator/lint 验证。

## 下一步建议

1. **立刻立 L1D/L2 显式 RAM wrapper 任务**：G2 已经证明仅 `ramstyle="M20K"` 不生效；本次 evidence 再次显示 cache data 阵列是 ALM/LUT 主导（342k ALM、0 MLAB、Block Memory Bits 几乎只在 EMIF/BRAM/FIFO）。下一步应仿照 `lcvex_bram_boot` 的 `altera_syncram` M20K 显式 wrapper 方案，为 `lcvex_l1_d_wb` 和 `lcvex_l2_wb` 的 data 阵列建立可综合 RAM 抽象。
2. 在没有 cache RAM wrapper 前，fitter 可能继续数十级分钟或无法收敛；可以先用 L2_WAYS=1/L1 更低容量做定性实验，但治本仍是显式 RAM。
3. 完成 cache RAM wrapper 后重跑 synthesis→fitter→STA→assembler，并复核 ALM（目标应远低于 342k）和 Block Memory Bits 增长。
4. 将本轮 Quartus 兼容性修复合入主 RTL 前跑 `make compile`/相关 lint，防止 Verilator 行为变化。
