## 关键边界和风险

1. 现有 `lcvex_core` 以 `fetch_pending`/`dmem_req_issued`/`memwb_committed_r`
   管理隐含单事务；`lcvex_mem_arb`、router、delay、RAM 以及基础 cache 都是
   single outstanding。不能仅把计数器改成 2 就声称 nonblocking。
2. `lcvex_l1_d_wb/l2_wb` 的 source/transaction 只覆盖部分上游/probe 接口，
   下游 M1-B beat 没有 echo；C2 `cluster_top` 对 line 请求的身份全 tie 0。F3a
   CACHE-WB-COH 必须先补完整 tuple 和 probe epoch，不能复用 0 作为“已配对”。
3. 当前 store 在 request accepted 时可能产生下游副作用，commit packet 到 WB
   才上报；这不是可直接扩展的 precise store buffer 语义。F3c 若不能证明 fault
   返回前零外部字节已写入，只能保留未退休请求槽并标记 blocked。
4. checkpoint 工具的 manifest/sidecar 校验和 RTL restore 会冲刷流水线，但基线
   没有 `docs/CHECKPOINT_PROTOCOL.md`，且 sidecar 没有 cache/MSHR 内容。F3a 必须
   以 drain-to-PoC、epoch bump 和 cache invalidate/quarantine 保证恢复后无 stale。
