## 目标与边界

在现有 C2 双核共享内存/目录式 MSI 框架中，交付一个可重复的双核性能
workload：core0/core1 通过共享 flag/mailbox 做 ping-pong、并行 reduction，
并比较同 cacheline 竞争与不同 cacheline 写入。改动仅限 TB/汇编/文档，不改
共享热点 RTL，不启动 Quartus，不引入 ACE/CHI/SVE，不宣称 A10/Fmax 或完整
ARM memory model。

## 实现摘要

- 新增 `tb/sv/lcvex_c2_perf_mc.S`：AArch64 双核裸机汇编内核，固定平铺在
  BASE+0x000（core0）和 BASE+0x100（core1），数据区在 BASE+0x2000 起。
- 新增 `tb/sv/lcvex_c2_perf_mc.hex`：由上述汇编生成的 32 位小端 flat image，
  共 2322 个 word，供 SV TB 用 `$readmemh` 加载。
- 新增 `tb/sv/lcvex_c2_perf_mc_tb.sv`：实例化现有 `lcvex_cluster_top`
  （COHERENCE_ENABLE=1, CORE_COUNT=2），加载镜像，启动两核，通过提交包
  中的 mem store 捕获 8 个 marker，记录各阶段 cycle 并做功能值检查。
- 新增 `tb/run_c2_perf_mc.sh`：可复现的 Verilator 构建/运行入口，
  VERILATOR_JOBS 默认 1。

Workload 内容：
1. **Mailbox ping-pong**：16 次。core0 写 mailbox，置 flag=1，DMB；core1
   等 flag=1，读 mailbox，回 ack=2，DMB。两核结束后写 ping_done marker。
2. **Parallel reduction**：64 个 word 初值为 1，core0/core1 各累加 32 个；
   core1 写 red_flag=1，core0 合并 partial0+partial1 写 red_result=64。
3. **Same-line contention**：两核各 32 次写同一个 64B line 的同一地址
   （BASE+0x2300），结束后双向 barrier 再进入下一阶段。
4. **Different-line stores**：两核各 32 次写各自独立 line
   （BASE+0x2400 与 BASE+0x2440），作为无跨核竞争对照。

TB marker 检查值：ping_done0=0x12345678、ping_done1=0x87654321、
red_result=64、red_done=0xABCDEF01、same0/same1/diff0/diff1 分别为
0x1111/0x3333/0x2222/0x4444。TB 只做功能正确性检查，不设性能通过/失败门限。
