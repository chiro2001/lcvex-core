## 尝试路径与结果

### 路径 A：复用原工程 Qsys/IP 生成

- 在隔离工程 `build\T-20260830-020\b5_top` 中复制了原 `quartus\qdb`（162 个文件）。
- 运行：
  ```powershell
  quartus_sh --flow compile b5_top -c b5_top -start ipgenerate -end ipgenerate
  ```
  **成功**，耗时约 8 秒，0 errors；检测到已有 Platform Designer 生成文件并跳过重新生成。
- 但运行 `quartus_syn` / `quartus_sh --flow compile -start synthesis -end synthesis` 后仍：
  - 进入 A10 顶层 elaboration；
  - 最终停在 `Starting IP generation for the debug fabric: alt_sld_fab_0` / `Qsys-generate ... alt_sld_fab_0.ip`；
  - 长时间无进一步日志，峰值约 20–21GB；
  - 没有完成顶层 synthesis。
- 结论：**独立 IP generate 不是完整解决；卡点在 synthesis 内部的 debug fabric/alt_sld_fab_0 生成。**

### 路径 B：复制原工程完整 DB 后 fitter-only

- 将原 `D:\Projects\fpga-altra\lcvex\quartus` 完整复制到 `build\T-20260830-020\orig_bu`。
- 在复制 QSF 上添加 `PARTITION` 分配，并成功导入：
  - `core` <- `core_nofp.qdb`
  - `coh` <- `soc_coh_reduced.qdb`
  - `ddr_bridge` <- `soc_axi.qdb`
  - `axi_master` <- `axi4_master.qdb`
  - `emif_adapter` <- `axi4_avalon_adapter.qdb`
- 运行：
  ```powershell
  quartus_sh --flow compile catapult_a10 -c catapult_a10 -start fitter -end fitter
  ```
  结果：
  ```text
  Error (16546): Cannot load synthesized database - ensure all earlier stages of the compiler have completed.
  ```
- 即使使用未导入 QDB、仅复制原 qdb 的 `orig_clean`，也得到同样的错误。
- 结论：**原 Quartus 编译 DB 绑定原项目路径/编译状态，复制到新目录后不能直接 fitter-only 加载；不能靠“复制原 DB”绕过顶层 synthesis。**

### 路径 C：SoC-only 顶层黑盒

- 沿用 FPGA-F3 的 `soc_top_bu` 实测：
  - 顶层 `lcvex_catapult_soc_top`，core/coh/AXI/EMIF 均为 black-box stub；
  - 运行约 85 秒达到 **31.3GB**，被 30GB 保护线中止。
- 结论：**即使没有 A10/Qsys，真实 SoC 顶层 glue/端口展开仍超过当前 30GB 单工程承受线。**
