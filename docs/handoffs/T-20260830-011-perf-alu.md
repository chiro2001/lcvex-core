## 目标

在 `baremetal/perf/` 下新增可重复的整数/控制流性能 workload，覆盖：

- 整数 ALU 依赖链延迟：ADD/SUB/AND/ORR/EOR
- 多路独立整数操作 ILP/吞吐：2/4/8 路
- 控制流：循环分支、条件分支、条件选择、直接调用返回、间接调用返回
- 乘除：MADD/UMULH/UDIV/SDIV 的延迟与两路吞吐形态

这些文件只做功能 sanity，不做性能通过/失败断言，不宣称 A10/Fmax 签核。

## 修改文件

- `baremetal/perf/t_alu_latency.c`
  - 提供 `run_test_alu_latency()`
  - 5 条单指令依赖链：ADD、SUB、AND、ORR、EOR
  - 每次迭代一条 volatile inline asm，固定默认 `PERF_ALU_ITERATIONS=100000`
  - 可通过 `-DPERF_ALU_ITERATIONS=N` 覆盖

- `baremetal/perf/t_alu_ilp.c`
  - 提供 `run_test_alu_ilp()`
  - 2/4/8 路独立 ADD 链，各自累计后合并
  - 固定默认 `PERF_ALU_ILP_ITERATIONS=100000`，可覆盖

- `baremetal/perf/t_ctrl_branch.c`
  - 提供 `run_test_ctrl_branch()`
  - 计数循环、强制条件分支（CBZ/B. taken/not-taken）、CSEL/CSINC、
    直接函数调用返回、经 volatile 函数指针的间接调用返回（BLR）
  - 固定默认 `PERF_CTRL_ITERATIONS=100000`，可覆盖

- `baremetal/perf/t_muldiv.c`
  - 提供 `run_test_muldiv()`
  - MADD、UMULH、UDIV、SDIV 各自的依赖链和两路独立版本
  - 固定默认 `PERF_MULDIV_ITERATIONS=100000`，可覆盖

未修改 `scripts/`、`Makefile`、`baremetal/microbench_main.c` 或现有
`baremetal/tests/t_*.c`；未创建 `perf_common.h`，每个文件自带最小宏，

## 构建/运行方式

P-INFRA 合入前可作为独立 C 函数编译，入口均为：

```c
int run_test_alu_latency(void);
int run_test_alu_ilp(void);
int run_test_ctrl_branch(void);
int run_test_muldiv(void);
```

使用项目现有裸机工具链逐文件编译：

```sh
AARCH64_GCC=aarch64-linux-gnu-gcc \
  aarch64-linux-gnu-gcc -O2 -ffreestanding -nostdlib -nostartfiles \
  -mabi=lp64 -mgeneral-regs-only -Ibaremetal \
  -c baremetal/perf/t_alu_latency.c
# 其余三个文件同理
```

P-INFRA 接入后，建议由 perf runner 按 `PERF_ONLY=<name>` 或声明表调用这些
`run_test_*`，在函数体外计 cycle/时间；本目录当前不修改 runner。
