## 交付内容

在 `baremetal/perf/` 下新增三个自包含性能 workload，均只提供功能 sanity
入口，不做性能“通过/失败”断言：

| 文件 | 入口 | 覆盖内容 |
| --- | --- | --- |
| `baremetal/perf/t_fp_scalar.c` | `int run_test_fp_scalar(void)` | FP32/FP64 FADD/FSUB/FMUL/FMADD（FMA）依赖链延迟；FP32/FP64 多路独立吞吐；FP32/FP64 有限迭代 FDIV 延迟 |
| `baremetal/perf/t_fp_fp16.c` | `int run_test_fp_fp16(void)` | _Float16 标量半精度 FADD/FSUB/FMUL/FMADD 多路吞吐 |
| `baremetal/perf/t_neon_vect.c` | `int run_test_neon_vect(void)` | 128-bit 整数 ADD、FP32 2S/4S ADD/MUL/FMLA、FP64 2D ADD/MUL/FMLA、Q register LDR/STR 吞吐 |

每个文件还提供 `run_perf_<name>()` 兼容别名，并在 `PERF_STANDALONE` 宏下
附带独立 `main()`，便于 P-INFRA 合入前单独编译/链接验证。

## 工具链与 FP 访问权限

- 交叉工具链为 `aarch64-linux-gnu-gcc`（GCC 16.1.0），支持 `_Float16`；
  `t_fp_fp16.c` 顶部使用 `#pragma GCC target("arch=armv8.2-a+fp16")` 使
  文件可独立编译出标量 H 指令。
- 这三个文件都不能用 `-mgeneral-regs-only` 编译，因为它们刻意使用
  FP/SIMD 寄存器。当前共享 `scripts/build-microbench.sh` 只编
  `baremetal/tests/t_*.c`，未受影响。
- 本 CPU 复位时 `CPACR_EL1.FPEN=00`，EL1 上 FP/NEON 指令默认触发 FP access
  trap。因此每个 `run_test_*()` 入口先写 `CPACR_EL1 = 3<<20`
  （FPEN=11），再执行 FP/NEON 指令。
- 未引入 SVE，未使用 `aarch64_sve` 或任何 SVE 指令。

## 实现要点

- 标量 FF 和向量 NEON 循环均使用 `volatile` inline asm，避免编译器删除、
  重关联或改写；依赖链使用单累加器，吞吐使用多路独立累加器。
- FP16 使用直接 `fadd/fsub/fmul/fmadd h` 指令，不经过软浮点。
- 向量 FP 使用 `fadd/fmul/fmla` 的 2S/4S/2D 形状；整数 ADD 使用 Q 寄存器
  4S 形式。
- 循环次数集中为可覆盖宏：
  - `FP_SCALAR_LAT_ITERS=1024`
  - `FP_SCALAR_TP_ITERS=512`
  - `FP_SCALAR_FDIV_ITERS=32`
  - `FP16_TP_ITERS=2048`
  - `NEON_TP_ITERS=1024`
  - `NEON_LDST_ITERS=512`
  后续 P-INFRA 或集成者可通过 `-D` 覆盖，控制运行时长。

## 当前 RTL 边界

- 当前 P7 实现尚未接 NEON 整数乘法（`MUL Vd.4S` 等为 UDEF），因此
  `t_neon_vect.c` 的整数部分覆盖 128-bit ADD，乘法/乘加覆盖向量 FP
  的 MUL/FMLA；若后续 RTL 补齐 NEON int MUL，可在此 workload 中增加对应
  独立链/吞吐 loops。
- 其它已选 FP/NEON 指令（标量 S/D/H 算术、NEON 2S/4S/2D FADD/FMUL/FMLA、
  Q load/store）按当前 RTL 功能集提供。

## 运行方式建议

当前 P-INFRA 尚未合入，可先按以下方式单独运行（以 `t_fp_scalar` 为例，
其余替换 `t_fp_fp16` / `t_neon_vect`）：

```sh
cd /home/chiro/projects/mycpu/lcvex-wt-T-20260830-013
aarch64-linux-gnu-gcc -O2 -ffreestanding -nostdlib -nostartfiles -mabi=lp64 \
  -DPERF_STANDALONE -I baremetal \
  -c baremetal/perf/t_fp_scalar.c -o /tmp/t_fp_scalar.o
aarch64-linux-gnu-gcc -O2 -ffreestanding -nostdlib -mabi=lp64 \
  -c baremetal/startup_mb.s -o /tmp/startup_mb.o
aarch64-linux-gnu-gcc -nostdlib -T baremetal/link.ld \
  -o /tmp/t_fp_scalar.elf /tmp/startup_mb.o /tmp/t_fp_scalar.o
aarch64-linux-gnu-objcopy -O binary /tmp/t_fp_scalar.elf /tmp/t_fp_scalar.bin
./build/microbench_runner/microbench_runner --image /tmp/t_fp_scalar.bin \
  --name t_fp_scalar --max-cycles 50000000
```

- 若运行器尚未构建，需要先在共享 worktree 构建 `microbench_runner`；本任务
  不修改该构建入口。
- 本任务没有实测 cycle 数；上述运行方式给出的是可重复的采集入口，真实
  cycle 数据应由集成者在合并 SHA 上按 P-line 计划采集。
