# LCVEX Catapult A10 25 MHz bring-up 计划

## 1. 目标和边界

首个 bring-up 里程碑只要求当前 AArch64 单核候选在 Catapult A10 上完成：

1. 板级 `clk_u59=100 MHz` 产生真实 `logic_clk_25=25 MHz`；
2. CPU 从确定初始化的 64 KiB M20K、`PC=0` 启动；
3. BRAM 常驻程序输出启动、校准和 DDR 诊断；
4. 使用轮询式 JTAG-UART 完成至少一次确定性的 `PING/PONG` 和字符回显；
5. 所有实现、物理和板级产物可由 source/tool/hash 追溯。

本里程碑不实现或宣称 Linux、UART IRQ、GIC/Timer 板级闭环、任意 payload
下载器、JIC/EPCQ 固化、Flash loader、断电自启动或发布验收。它们只能在首个
轮询交互里程碑完成后另立任务。

## 4. 实现契约

### 4.1 时钟和复位

计划拓扑为：

```text
clk_u59       = 100 MHz board input
logic_clk_25  = clk_u59 / 4, CPU/SoC/JTAG-UART/SFL logic domain
qsys_ref_100  = clk_u59, only where the generated Qsys contract truly requires it
clk_y3        = 266.667 MHz EMIF reference, unchanged
emif_usr_clk  = generated by EMIF, unchanged
```

T-038 必须读取生成的 Qsys 连接，证明 `clk_100_clk` 的真实消费者；不能只因端口名
含 `100` 就重接，也不能把 EMIF reference 或 metadata 改成 25 MHz。如果把 Qsys
辅助域与 CPU 域分离会形成新功能 CDC，必须停止 lane 并由集成者重新设计。

SDC 必须同时声明 `clk_u59=10 ns`、真实 `/4` generated clock `sys_clk_25=40 ns`
以及原 `clk_y3=3.750 ns`。RTL clock anchor 与 TimeQuest pin 必须一一对应。
`LOGIC_POR_CYCLES=65536` 在 25 MHz 下约为 2.62 ms；reset 值和释放时机不变。

### 4.2 地址、BRAM和镜像

首版固定地址：

```text
BRAM          [0x00000000, 0x00010000)
BRAM stack    [0x0000F000, 0x00010000)
DDR           [0x40000000, 0x48000000)
JTAG DATA     0x09000000
JTAG CONTROL  0x09000004
PLAT_STATUS   0x09003000
```

当前 top 使用 64 KiB BRAM，但 package/README/linker 含 1 MiB 假设。T-039 必须
以 64 KiB 为唯一板级事实并修正 linker/stack；不得把越界隐藏成更大 decode window。

同一个 AArch64 ELF 生成：

- 仿真：逐字节 little-endian HEX；
- Quartus：`WIDTH=64, DEPTH=8192` MIF，byte0 位于 word bits `[7:0]`；
- artifact：ELF/BIN/HEX/MIF 均记录 SHA-256、字节数、工具版本和 source SHA。

生成器必须逐字节回读 MIF并与 BIN 比较。综合 `altera_syncram` 必须使用确定的
`init_file`，不再允许 `BOOT_HEX_FILE=""` 和 `power_up_uninitialized="TRUE"`。
MIF 是 physical payload，必须进入远端 manifest/QSF closure 和下载后 hash 复核，
但 build 产物不提交 Git。

### 4.3 BRAM常驻程序

程序永远先进入可诊断 monitor，不跳入未初始化 DDR。启动输出最多占用一个
64-byte TX FIFO：

```text
LCVEX25 BOOT
CAL-OK | CAL-FAIL | CAL-WAIT
DDR-OK | DDR-FAIL
READY
```

校准失败或超时也必须输出状态并进入 `READY`；DDR 失败不能使串口诊断不可用。
命令保持单字符，避免首轮引入二进制 framing/CRC/SHA/download loader：

```text
p  -> PONG
?  -> CLOCK/CAL/DDR 状态
m  -> 重新运行 DDR magic write/readback
其他可打印字符 -> 原样回显
```

DDR 成功必须同时满足软件 readback 和 SoC TB 中真实 DDR adapter read/write 计数；
不能只从 cache 读回自己写入的数据。如果 reset cache policy 不能保证 bypass，任务
必须使用现有架构支持的 clean/invalidate + DSB/ISB，不能加入私有未验证编码。

### 4.4 JTAG-UART

LCVEX 使用标准地址，不移植 VexRiscv 的 address-bit `[13]` workaround：

- Avalon address 0：DATA；CPU 地址 `0x09000000`；
- Avalon address 1：CONTROL；CPU 地址 `0x09000004`；
- DATA read：bit15=`RVALID`，bits7:0=character；读取会弹出 RX FIFO；
- CONTROL read：bits31:16=`WSPACE`；bit10 `AC` 只是 host activity；
- TX 写入前检查 `WSPACE != 0`，但启动 marker 不能因 host 尚未连接而永久挂死；
- bridge 请求只产生一次 Avalon 副作用，response 在 `rsp_ready` 前稳定；
- 首版只轮询，不依赖 `.irq`、GIC或Linux driver。

T-040 先验证当前 `req.addr[2]` 实现；只有 focused TB 证明 defect 才改 RTL。
不得直接编辑/覆盖厂商生成的生产 JTAG-UART HDL。RX 注入和FIFO模型放在独立测试
文件，T-037 再串行接入 SoC integration TB。

  `nios2-terminal --device=1 --instance=0`；

  `Loading final database`复用stale DB而让RTL修改未进入网表；

- `Can't find JTAG Server`优先检查client.conf、工作目录、PID和端口，不能盲目重烧。

## 6. 验证门

### L0

- AArch64 ELF section、entry、stack和反汇编；
- BIN/HEX/MIF逐字节一致、MIF深度/宽度/未用区为0；
- 25 MHz分频和SDC静态锚点；
- UART DATA/CONTROL常量和生成IP接口核对。

### L1

- divide-by-four波形、POR/reset；
- BRAM reset-vector、MIF init、边界/跨界拒绝；
- UART DATA/CONTROL、waitrequest、RX pop、TX full、held response、reset；
- cal-ready/fail/timeout及DDR magic写读。

### L2

完整Catapult SoC仿真必须从 `PC=0` 的同源BRAM镜像执行，观察：

- `LCVEX25 BOOT` 和 `READY`；
- 注入 `p` 后收到 `PONG`；
- 可打印字符回显；
- cal失败时无DDR请求但UART仍可交互；
- cal成功时真实DDR adapter计数和`DDR-OK`。

QEMU只可作为AArch64程序的可选辅助，不修改QEMU fork，也不能替代SoC/MMIO仿真。

### L3和physical

- T-037合并SHA在detached gate worktree跑Gate D；本地heavy取得`local`，
  `VERILATOR_JOBS=1`，记录实际峰值；
- T-042在fresh远端probe严格串行synthesis→fitter→STA/custom，取得`gamepc`；
- `sys_clk_25`必须为40 ns；setup/hold/recovery/removal/min-pulse全非负；DDR、
  metastability、MIF使用和source closure必须通过；
- T-042禁止assembler。T-043只有用户明确授权才运行一次assembler。

## 8. 执行协议

- 所有写任务使用唯一topic branch和direct sibling worktree；派发子代理省略model参数；
- T-038/039/040可并行实现，成员不跑heavy；T-037按登记顺序汇入batch candidate；
- `resource-lock`返回75即等待，禁止裸跑；本地与GamePC可在路径隔离时流水重叠；
- T-035完成前，T-041不得触碰JTAG，T-042不得进入GamePC队列；
- physical等待采用事件驱动和最长1小时`wait_agent`，不频繁轮询；
- evidence保存命令、source SHA、seed、工具、资源、artifact hash；大日志/数据库/SOF
  留在ignored或远端独立目录，不进Git；
- T-043 assembler和T-044 JTAG是两个独立权限门，任何一个授权都不自动授权另一个。
