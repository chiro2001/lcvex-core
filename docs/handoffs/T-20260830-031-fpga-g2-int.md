## 方案

主 RTL `rtl/lcvex_bram_boot.sv` 改为选择式 wrapper：

- 当 Quartus 综合定义 `SYNTHESIS` 时，实例化同文件中的 `lcvex_bram_boot_altsyncram`：
  - 显式 `altera_syncram`，`BIDIR_DUAL_PORT`，`ram_block_type=M20K`；
  - 64-bit word 组织，port A 给请求读/写，port B 给 debug 读；

  - 完整 byte-address `logic [7:0] mem[0:DEPTH_BYTES-1]`；

## 未对齐/跨字访问风险与 lane/旋转方案

- 行为级 fallback 是权威语义：任意字节地址、跨 8B word 的读写都保持原行为。
- 显式 M20K wrapper 是 64-bit word 组织，已实现 word 内 lane 旋转：
  - 写：`byteena = req.strb << addr[2:0]`，`data = req.wdata << (addr[2:0]*8)`；
  - 读：`rdata = req_q >> (addr[2:0]*8)`；
  - debug 读同样右旋。
- 未实现跨 word 拆分。显式实现检测 `(addr[2:0] + hi_byte(req.strb)) >= 8` 后返回 fault，避免静默丢字节/写错。
- 在现有 SoC boot/缓存路径下，BRAM 下游通常看到 L1/L2 的 8B 对齐 refill/writeback，以及 4B 对齐取指；因此该限制不影响当前 boot smoke。
- 后续若要支持非缓存未对齐跨 word 访问，建议：
  1. 在 wrapper 内做两拍拆分（先写/读低 word，再高 word），或
  2. 在 SoC 路由层禁止/降级未对齐 BRAM 非缓存访问并显式 fault，
  3. 或保留行为级模型用于非缓存路径，仅在缓存回写路径使用显式 M20K。
  当前选择 3 的变体：Verilator 用行为级，综合路径用显式 wrapper；跨 word 在综合路径 fault。
