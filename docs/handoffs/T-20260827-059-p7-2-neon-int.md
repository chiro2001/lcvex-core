## 交付摘要

本任务在复用 P7-0/P7-1 V0–V31 raw 128-bit state、FPEN 和 scalar commit/memory
边界的前提下，实现了受限 Advanced SIMD/Q 整数垂直切片：Q move/MOVI、bitwise、
逐 B/H/S/D lane add/sub、signed/unsigned compare、非饱和立即 shift，以及单 Q
unsigned-offset load/store。结果只经一个 `vec_write_count=1` effect 在
`commit_fire` 更新；Q memory 的架构语义是一条 commit，内部镜像两个连续 8B
请求，两个 strobe 都为 `0xff`。

RTL 使用 `rtl/lcvex_neon_int.sv` 的固定宽度 raw-bit datapath；没有 host SIMD、
host float、epsilon 或宽松 NaN 比较。V forwarding/load-use hazard 已跨 scalar
FP 与 NEON 单元闭合。

## 两条 Q store fault 证据

### 合规路径（通过）

完整 16B preflight 在第一段 request 前检查自然对齐和完整地址窗口；正常
`lcvex_soc_tb` memory slave 遵守“已预检 Q store 不返回 response fault”契约。
assertion-enabled Cocotb `test_p7_2_neon_pipeline` 可重放验证一个 Q store 作为
一个 commit 携带 `mem`/`mem2` 两条连续 8B store，`WSTRB=0xff`；核心 SVA 同时
检查 first accept 前的两个半段窗口/对齐和 response fault 禁止条件。

### 非法路径（expected-reject，非通过）

`lcvex_neon_fault_bfm_tb` 故意在第一段 `request-accept` 已发生后，让第二段
response 返回 `fault=1`。现场日志先记录：

```text
FAULT_BFM first request-accept addr=0x44002000
FAULT_BFM second response fault addr=0x44002008 after first accept
SVA failure: rtl/lcvex_core.sv:3529
```

该运行保持 `--assert`，退出码为非零；它是 `expected_reject`，不是绿色测试。
当前普通 `mem_req` 在 accept 即产生写副作用，没有 rollback，因此本切片只在
上述受限下游契约下闭合，绝不宣称任意第二段 fault 的原子回滚。若未来 AXI/Cache
要求支持任意 fault，必须另开事务任务，增加 prepare/commit/abort 或等价可回滚
接口，并通过新的 faulting BFM；不能只改文档。

## 重点边界结果

- `STR Q` 对齐 fault：ESR WnR=1，FSC=0x21，无任一 store。
- aligned `SRAM_TOP` range fault：ESR WnR=1，FSC=0x10，无任一 store。
- `memwb_exc` 有效时 `fetch_merge_wb` 条件显式为假，DABT 优先。
- `STR Q` 位于映射页末、下一条取指为 IABT 时，fetch-merge 保留 `mem2`；A76
  required 20 条锁步通过，IABT fetch ESR WnR=0。
- `LDR S/D -> NEON`、`LDR Q -> scalar FP/STR D` 的 V hazard、随机延迟和
  commit backpressure 均有定向覆盖。
- Q=0/D-register、scalar Advanced SIMD、非法 immh、lane/structured/pair、
  saturating/narrow/widen/permute/table/across-lane/crypto/NEON FP 等未选编码
  均按 UDEF 负测覆盖。
