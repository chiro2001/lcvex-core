## 阻塞原因与分析

1. 当前 main 的 SystemVerilog 并不被 Quartus 21.4 直接接受；即使语法补齐后，B5 SoC
   在 `A64_FP_SIMD=0` + 4KB L2 的缩减配置下仍在 elaboration 阶段达到约 45GB 私有内存并异常终止。
2. 这说明真正的大头不只是 FP/NEON 或 L2 几何，而是 core/cache/coherence/AXI 的整体
   elaboration/netlist 展开；单靠现有参数缩减不足以规避远端 64GB 物理内存限制。
3. 按 FPGA-E 结论，单工程 partition 无法降低 elaboration 峰值；必须验证 block-based
   bottom-up 是否真的能跳过顶层 RTL 重综合，且需要把最大分区（L1D/L2/coh）继续结构性拆小。
4. T-067 尚未解除：仍需要外部资源（更大内存/页文件/更多机器）或更深入的 RTL/结构拆分。

## 下一步建议

1. 不要重复启动完整 B5 full flow；重复 soc_only 大概率复现本高内存退出。
2. 继续按模块/子模块 standalone synthesis（先跑 l1_d_wb、l2_wb、soc_coh 的更长时隙），
   在远端 64GB 下确认哪些分区仍无法单独通过。
3. 若远端仍无法容纳，优先方向：
   - 将 `lcvex_l2_wb` / `lcvex_l1_d_wb` 继续做多周期/按 beat 拆分，或抽独立 RAM wrapper；
   - 对 `lcvex_catapult_soc_coh` 进一步拆 wrapper；
   - 使用更大物理内存/页文件，或换更高内存的远端主机。
4. 在 block-based bottom-up 真正验证“顶层 import 后不重综合”之前，不支持 full flow。
