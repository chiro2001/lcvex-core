## 摘要

本次只做静态预研，没有修改 RTL/TB/sim/Makefile，也没有运行生成器、构建、仿真、QEMU
或 Quartus。主结论如下：

* F1a 可以把 FIFO 放在 core 内，保留 I-L1 的 64B 完整行 refill 和公共
  `mem_req_t/mem_rsp_t` ABI。为避免当前 response 无身份字段造成误配，F1a 固定一个
  MMU 取指翻译、一个 I-L1 读在途；flush/reset 后用本地 `fetch_token={epoch,seq,slot,pc_va}`
  和 stale quarantine 消费旧 response，再发新请求。
* FIFO entry 必须保存 epoch、VA PC、32-bit instruction、fault/FSC；flush 优先于
  push/pop，stale response 只能 drop，不能入 FIFO、译码或合并 IABT。系统/维护/ERET/WFI/
  IRQ 边界都清年轻项并提升 epoch；`commit_ready=0` 时不得 pop 或更新架构状态。
* F1b 不能在现接口下默认实现。I-L1 当前任意 refill beat fault 都通过同一个
  `mem_rsp.fault` 上抛，若 critical word 已被消费再遇 later fault，既不能精确回滚，
  也不能把相邻 beat fault 重报为当前 IABT。必须先增加 background-fault/line-completion
  契约，或证明整行无 later fault；否则保持 `FETCH_EARLY_RESTART_ENABLE=0`。

## 关键风险

1. **无身份响应**：如果任何适配器允许两个未带 token 的取指事务同时存在，F1a local
   quarantine 不成立，必须停止并改做 sideband 协议。
2. **系统排空**：FIFO 的年轻取指不能越过 IC/TLBI、MMU 配置 MSR、ERET、WFI 或 IRQ
   边界；提前取回的 system target 只能 held，不能进入 ID/EX。
3. **IABT 合并边界**：保持当前 older `next_pc == fault_pc` 或 system target merge
   规则；复位后无 predecessor 的 standalone fetch fault 不得伪造 packet，应另立协议。
4. **F1b 精确 fault**：later refill beat fault 必须有明确 background 语义和最后 beat
   metadata 门控；任何含糊吞 fault、半行 hit 或伪 IABT 都是停止条件。
