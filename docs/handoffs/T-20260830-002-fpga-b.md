## 只读分析

- `lcvex_l2_wb` 默认 `SETS=256, WAYS=2, LINE_BYTES=64`。
- 数据阵列：
  ```text
  data[0:SETS-1][0:WAYS-1][0:LINE_BYTES-1] = 256 * 2 * 64 = 32768 bytes
  ```
  `cache_chunk/pack_line` 等组合函数以动态 `idx/way/beat` 读该阵列，会展开为非常大的 mux。
- 目录/状态机：`ST_GLOBAL_SCAN/ST_DRAIN_SCAN` 已经逐 set/way 单拍推进，不是全组合扫描；
  主要成本来自数据阵列 mux、metadata/tag 比较和 8-beat refill/writeback 搬运逻辑。
- 可选方向：
  1. **减少 SETS/WAYS**：直接降低数据阵列规模（本项目采用）。
  2. **多周期化**：把大 mux 拆成按 beat 或 byte 的分阶段读取；正确性需重新验证，改动较大。
  3. **拆分 module**：把 data array 抽成独立 RAM wrapper/partition，减少单模块综合压力。
  4. **Quartus partition**：把 core/L1D/L2 设为独立 partition；需要改动 QSF，且不改变 RTL。
- 影响边界：C2 使用 `lcvex_l2_cluster`，不实例化 `lcvex_l2_wb`；因此本次只改 FPGA A10 平台配置，
  不触碰 C2/RTL 功能、不触碰 CORE_COUNT=1 核心路径。

## 改动

文件：`fpga/catapult_a10/rtl/lcvex_catapult_a10_top.sv`

- 给 `lcvex_catapult_a10_top` 增加参数：
  ```systemverilog
  parameter int L1_SETS = 64,
  parameter int L2_SETS = 64,
  parameter int L2_WAYS = 1
  ```
- `lcvex_catapult_soc_top` 实例改为使用这些参数。
- 旧配置：`L2_SETS=256, L2_WAYS=2`（32KB L2）。
- 新配置：`L2_SETS=64, L2_WAYS=1`（4KB 直接映射 L2），用于 FPGA-B 合成/起板；
  明确不作为 Linux cache-capacity 声明。

### 预期综合收益

- L2 数据阵列规模：32768B -> 4096B，**减少 8x**。
- SET 索引位宽：8 -> 6；TAG 位宽 50 -> 52（地址覆盖不变）。
- 预计显著降低 `lcvex_l2_wb` 的 mux/综合 netlist 大小和 synthesis 时间；未运行 Quartus 验证。
