三个文件均为自包含实现，未依赖尚未合入的 `perf_common.h`；每个文件在
`PERF_STANDALONE` 宏下附带一个独立 `main()`，方便当前阶段单独编译/链接验证。

## 设计要点

- 所有测试只返回 `0`，不做性能“通过/失败”断言。
- 结果数据（读/写/拷贝、pointer chase、load-use/store-forward、LDP/STP）
  通过 volatile 指针和共享 `perf_sink` 保留，避免优化器删除。
- 测试 buffer 放在 128 MiB 物理 RAM 窗口内的固定 scratch 地址：
  - `t_mem_seq`: src `0x45000000`、dst `0x45800000`
  - `t_mem_random`: `0x45100000`
  - `t_mem_ldst`: `0x45200000`

  这样 8 MiB 顺序 buffer 不依赖修改共享 `baremetal/link.ld`，也不扩大镜像 BSS。
- 迭代次数集中在少量宏/表中，必要时可调整以控制运行时长。

## 运行方式建议

当前 P-INFRA 尚未合入，推荐先按以下方式单独运行（P-INFRA 合入后接入统一
`PERF_ONLY`/JSON 流程）：

```bash
# 以 t_mem_seq 为例（其余把 t_mem_seq 换成 t_mem_random / t_mem_ldst）
cd /home/chiro/projects/mycpu/lcvex-wt-T-20260830-012
aarch64-linux-gnu-gcc -O2 -ffreestanding -nostdlib -nostartfiles -mabi=lp64 \
  -mgeneral-regs-only -DPERF_STANDALONE -I baremetal \
  -c baremetal/perf/t_mem_seq.c -o /tmp/t_mem_seq.o
aarch64-linux-gnu-gcc -O2 -ffreestanding -nostdlib -mabi=lp64 \
  -c baremetal/startup_mb.s -o /tmp/startup_mb.o
aarch64-linux-gnu-gcc -nostdlib -T baremetal/link.ld \
  -o /tmp/t_mem_seq.elf /tmp/startup_mb.o /tmp/t_mem_seq.o
aarch64-linux-gnu-objcopy -O binary /tmp/t_mem_seq.elf /tmp/t_mem_seq.bin
./build/microbench_runner/microbench_runner --image /tmp/t_mem_seq.bin \
  --name t_mem_seq --max-cycles 50000000
```

- 运行器输出会给出整段 `PASS` cycle 数；当前三个 workload 不输出内部分项。
- 如果运行器尚未在当前 worktree 构建，需先构建 `microbench_runner`（该步骤属于
  P-INFRA/共享验证，不在本任务中执行）。
- 固定 scratch 地址依赖当前 128 MiB RAM 模型；若回退到旧 1 MiB SRAM 模型需改用
  小 buffer 或调整地址。
