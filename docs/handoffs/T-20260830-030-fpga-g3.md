## 结论（有效/无效）

1. **有效：SoC-only 黑盒+shim 基线复测通过**
   - `soc_bu_altsync_16k` 重跑：PASS，0 errors，10876 warnings；
   - 墙钟约 8s，峰值私有内存 619 MB，峰值 VM 749 MB；
   - 与 G2 记录一致，确认实验环境稳定。

2. **有效：真实 A10 顶层 + shim 不再卡在 `alt_sld_fab_0`**
   - 使用 G2 显式 `lcvex_bram_boot_altsyncram` + 同名 `lcvex_bram_boot_shim`，配合 T-16/T-20 的 core/coh/AXI black-box stubs；
   - 完整实验 flow（ipgenerate→synthesis→fitter）第一次在 **synthesis 成功**（2m38s），之后仅因隔离副本 SDC 中 `get_clocks/get_registers -quiet` 不被 Quartus 21.4 接受而卡在 fitter 的 automatic periphery placement；
   - 将实验 SDC 的 `-quiet` 改为 `-nowarn` 后：
     - Fitter 成功：4m04s，0 errors；
     - STA signoff 成功：约 10s（flow report）/20s（监控），全部 setup/hold/recovery/removal/minimum pulse width slack 为正；
     - Assembler 成功：约 35s（flow report）/46s（监控），产出 `a10_top_altsync.sof`（36,842,136 B，SHA256 `0466F1A5E7DBFB13A0645331DCEF3014DA327389E1F17EA9914F850AF3082334`）；
   - 因此“真实 A10 顶层卡在 alt_sld_fab_0”的原有判断需要修正：**只要行为级 BRAM 被显式 altsyncram 替代，debug fabric 自动生成不是 blocker**；之前看到的 20+ min/21GB 是行为级 BRAM 在 elaboration/综合中消耗资源，不是 debug fabric 本身。

3. **有效对照：同一 A10 黑盒但保留行为级 `lcvex_bram_boot` 会重新陷入高内存**
   - `a10_top_behav`（仅替换回行为级 BRAM，其余与 A10+shim 相同）：
   - 被监控在 5m27s 时强制中止，峰值私有内存 21.7 GB，未产生 synthesis report；
   - 证明 altsyncram shim 是本次通过的关键，而不是“新工程刚好运气好”。

4. **无效：完整原工程路径副本不能解决 fitter-only `Cannot load synthesized database`**
   - 复制非 `build` 的整个 `D:\Projects\fpga-altra\lcvex` 到 `D:\Projects\fpga-altra\lcvex_bu_T30`，保持内部 `quartus/qsys/rtl/flash/jtag_uart` 层级；
   - `quartus_sh --flow compile catapult_a10 -c catapult_a10 -start ipgenerate -end ipgenerate`：PASS（约 8s，0 errors）；
   - `quartus_sh --flow compile catapult_a10 -c catapult_a10 -start fitter -end fitter`：FAIL（立即，exit 3），精确错误：
     `Error (16546): Cannot load synthesized database - ensure all earlier stages of the compiler have completed.`
   - `quartus_sh --flow compile catapult_a10 -c catapult_a10 -start synthesis -end synthesis`：实验性启动完整真实 A10 顶层；在 45GB 保护线被中止，运行约 11m11s，峰值 PM 45.6GB / WS 44.2GB，未产生 synthesis report；

## 下一步建议

1. 将 G2 显式 `altera_syncram`/`altsyncram` BRAM wrapper 正式纳入主 RTL，替换行为级 `lcvex_bram_boot`。
2. 在 A10 黑盒+shim 已经走通 synthesis/fit/STA/asm 的基础上，逐步把 black-box stubs 换回真实 core/coh/AXI（或导入现有 partition QDB），以确认完整 SoC 是否也能在中等内存下完成。
3. 如果继续使用 AUD-04 SDC 块，必须把 `-quiet` 改为 `-nowarn`（或改写为 `catch`/`get_clocks -nowarn`），否则 fitter 自动外围布局失败。
4. 原路径副本方向可放弃；若要 fitter-only，需要更完整的 DB/整 SoC QDB，或先在更高内存机器上完成真实 synthesis。
5. 下一步优先评估 L1D/L2 显式 RAM 包装：当前 A10+shim fit 仍只解决 BRAM；cache 数据阵列仍可能用 LEs 实现（G2 已证 ramstyle 无效）。
