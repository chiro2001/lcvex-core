## 1. 结论

- 真板（Catapult A10，JTAG ID `0x02E060DD`）已用本候选跑通：
  BRAM loader 从 EPCQ 读取 LCVEX payload → 校验 kernel/DTB CRC → `LOAD OK; EL1`
  → `Linux version 6.6.0` → `ttyJ0` (irq 11) → `Run /init as init process` →
  `LCVEX Catapult A10 /init ready`。
- JTAG-UART 交互：`help` 返回 `commands: help, echo [text], sleep, about`，
  `echo LCVEX_UART_OK` 返回 `LCVEX_UART_OK`，提示符为 `lcvex>`。
- 断电冷启动同样通过：用户真实断电再上电后，**没有任何主机下载动作**
  （该窗口只运行了只读的 `jtagconfig` 和 `nios2-terminal`），串口完整输出
  loader → `LOAD OK; EL1` → `Linux version 6.6.0` → `ttyJ0` → `Run /init` →
  `LCVEX Catapult A10 /init ready`，并再次回答 `help` 与 `echo LCVEX_UART_OK`。
  也就是说 FPGA 配置与 payload 都来自 EPCQ Flash。
- 冷启动后的同一条串口还跑了 `sleep`（`nanosleep` 1 秒）：返回
  `sleep: 1 second elapsed`，随后 `echo AFTER_SLEEP_OK` 返回 `AFTER_SLEEP_OK`。
  这覆盖了 EL0 `svc` 系统调用、内核 hrtimer/scheduler、GIC PPI 30 定时器中断与
  返回用户态的完整路径。

  loader 只打印 41 字节就继续启动，这 41 字节会留在 JTAG-UART 的 TX FIFO 里等主机
  读取，所以即使在启动中途才接上终端，也能拿到从头开始的完整冷启动记录。

## 2. 关键改动（相对 B25 基线）

- `rtl/lcvex_l1_d_wb.sv`：跨 64 字节行边界的 load/store 拆成两段走同一 L1
  查表/refill 路径（修掉首个 printk 的 NUL 与尾字节丢失）。
- `rtl/lcvex_core.sv`：可选的板级真实时钟 Generic Timer 模式，QEMU 指令计数模式
  仍是默认。
- `rtl/lcvex_catapult_soc_top.sv` / `lcvex_catapult_soc_axi.sv`：GIC/Timer/JTAG-UART
  IRQ 接线、EPCQ 只读 aperture（含等待超时）、按 byte strobe 生成 AXI size、
  单拍读返回对齐到字节 0。
- `rtl/lcvex_gic.sv`：把 96 项串行优先级扫描改成平衡锦标赛树。第一次 post-fit STA
  在 `sys_clk_25` 上是 **-103.394 ns**（143 ns 组合链，路径
  `soc|board_gic|active_r[0] -> pending_r[30]`）；改成树形归约后同一流程为
  **+5.723 ns**，全时钟 TNS 0。
- `fpga/catapult_a10/jtag_uart/...zesttkq.v`：生成的 JTAG-UART 在**首字节**就拉
  RX 中断（原来要 56 字节），否则阻塞式 TTY 读永远收不到命令。
- `fpga/catapult_a10`：QSF MIF 指向 `linux-loader/linux_loader.mif`，补上
  `rtl/lcvex_gic.sv`；`check_platform.py` 现在要求仿真 filelist 里的每个
  `rtl/*.sv` 也出现在 QSF 中（正是漏 GIC 那次综合失败的直接守卫）。
- `fpga/catapult_a10/boot/linux_flash_cof.py`：EPCQL1024 COF 生成器（相对 Intel
  HEX + `hex_offset` 只加一次），带主机测试。
- `configs/linux-catapult-lite.fragment`：把 KPTI-off 这一板级决定写进 tracked
  fragment（`CONFIG_EXPERT=y` + `# CONFIG_UNMAP_KERNEL_AT_EL0 is not set`）。

## 4. Flash 写入的两个坑（都已解决）

1. `quartus_pgm ... -o "p;<file>"` 里的电缆名与 operation 含空格，PowerShell
   `Start-Process -ArgumentList` 不会自动加引号，必须显式构造带引号的命令行。
2. 直接写 JIC 会报 `Error (209062): Flash Loader IP not loaded on device 1`。
   必须先用 Quartus 自带 helper 设计配置 FPGA：
   `helper_sofs/sfl_enhanced_10_02e060dd.sof`（EPCQL1024/1 Gbit、JTAG ID
   `02e060dd` 对应的变体），再写 JIC。写入 8m27s，0 errors。

写 Flash 前已核对 golden 恢复包仍在位：
`a10-linux-riscv/dist/golden/output_file.jic`（`86ee77ad…`）与
`dist/golden/vex_soc_ddr.sof`（`290ab3cf…`）。

## 6. 边界与风险

- 冷启动已通过（配置与 payload 均来自 Flash），但它只证明单核 25 MHz no-FP 的
  本候选镜像；不代表 DDR 压力、full-FP 或长时间运行。
- 该候选是 no-FP（`A64_FP_SIMD=0`）板级 profile，软件不得执行 FP/NEON；`/init`
  只用整数指令，尚未跑 BusyBox。
- FW 默认 SWIOTLB 会预留 64 MiB（`Memory: 57608K/131072K available`），板卡上
  只多几十毫秒，却会让行为级仿真慢很多倍。
- `sys_clk_25` 建立余量 +5.7 ns 是 post-fit 结论；EMIF 时钟余量最小 0.18 ns。
- `ipgenerate` 会重写 `Qsys_bb.v` 与 QSF（仅注释/换行级别），远端审计记录了这两处
  drift，RTL 无 drift。
