## 过程中发现与处置

1. Quartus 21.4 不接受 Verilator 可接受的若干语法，逐项改写：
   - `rdg(...)[a:b]` 函数结果切片 → `rdg_low/rdg_bit` 辅助函数；
   - `insn[22:19][3]` → 局部变量 `immh`；
   - enum 字面量宽度 → 与 enum 宽度一致（`alu_op_t`/`sys_reg_t`）；
   - `bitfield_op(...)[31:0]` / `clz64(...)[6:0]` → 64 位临时再取位；
   - neon double lane 64-bit 索引越界 → `index[0]` 选择半个 Q；
   - 变步长/变量边界循环 → 固定次数或位段扫描；
   - 动态 lane 切片（`index*N +: N`）→ 移位 + 固定宽度低位；
   - BRAM `prog_we` 写口 → `translate_off` 仿真专用，避免多驱动。
2. 首轮 smoke 因 BRAM 写口移入复位分支失败；改为独立时钟沿写口后恢复
   PASS，再改为 `translate_off`（综合移除）解决 Quartus 多驱动。
3. 远端旧 compile 子进程未随 SSH 会话退出而终止，会与新一轮 full flow
   争资源；已终止旧进程后重跑。
4. NEON 移位改写引入 Quartus `16753` warning（“移位次数可能大于宽度”）：
   调用侧已按 lane 数量约束索引，语义不受影响，列入 known_limits。
5. 远端 b5k 卡在 Synthesis 的根因是内存耗尽：首轮 b5i 的 SSH 会话被中断后
   子进程未退出，与 b5j/b5k 的 Quartus 进程叠加（Session 0，管理员与
   SYSTEM 计划任务均无法终止），Free 内存降到 0.5 GB。已记录为环境性
   blocker，不改变 RTL 结论。
