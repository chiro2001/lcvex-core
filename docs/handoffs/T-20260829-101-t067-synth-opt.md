## 目标
定位 T-067 中 B5 SoC 在 Quartus Analysis & Synthesis 达到 ~77GB 私有内存 OOM 的
RTL 热点，验证关闭 FP/NEON、去掉 EMIF/平台 IP 等缩减方案，提出下一步优化建议。

## 结论
- **去掉 Qsys EMIF/SFL/JTAG-IP/board wrapper 后，独立 `soc_only` 合成仍在约 4-5 分钟
  达到 70GB 私有内存并停滞**。因此 77GB OOM 的热点在 B5 SoC 内部 RTL
  （core/cache/AXI/SoC），不是 DDR/EMIF/平台 IP。
- **A64_FP_SIMD=0 的独立副本 `soc_nofp` 同样达到 70GB 并停滞**。当前 RTL 中
  `A64_FP_SIMD` 参数没有真正 gate 掉 FP/NEON 实例，所以关闭 FP 并不能降低内存。
- **单独 `lcvex_decode` 可稳定完成 synthesis**：33s，峰值虚拟内存 682MB，
  14,667 logic cells / 24,284 device resources，0 errors。decode 不是 OOM 主因。
- **core 级 standalone 快速失败**：`lcvex_fp_scalar.sv` 中超过 64-bit 的除法触发
  Quartus `lpm_divide LPM_WIDTHN must be <= 64`（line 507/508），峰值仅 ~1.9GB。
  这是一个独立的 Quartus 可综合性问题，与 OOM 不同。
- 真正热点尚未细化到单个模块；最可能集中在 core 整体展开、cache/coherence、MMU
  或 AXI bridge。
