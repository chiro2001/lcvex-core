## 根因

1. **默认迭代/规模偏大**：ALU/CTRL/MULDIV/MEM 等 workload 的原始默认参数在单发射顺序核上需要数百万甚至数千万 cycle。
   - 例如 `alu_latency` 100k 次链式迭代约 5.02M cycle；
   - `ctrl_branch` 100k 次约 11.7M；
   - `muldiv` 100k 次约 85M；
   - 原 mem 顺序/随机/load-store buffer 规模也导致远超 5M。
2. **旧 build/microbench_runner 不含当前 FP/NEON RTL**：仓库已有 runner 是 2026-08-27 的旧二进制。FP/NEON workload、以及被编译器自动插入 Q/D 寄存器栈操作的整数 kernel（CRC/矩阵/排序/哈希等）都会在 FP 未使能或旧模型不支持时挂起，而不是单纯“慢”。因此即使减小 kernel 规模，旧 runner 下仍 timeout。
3. **目标 RTL 当前不支持的少量 FP 指令**：重建后的 runner 仍不能执行 `fmov` GPR<->FP、FP16/单精度 `fcmp`、向量 `movi`/`fmov v#imm`、`stp q` 前置于 CPACR 使能等路径；需要调整 workload 写法避开这些指令。

### 代码/构建改动

- 所有 workload 的参数宏补充 `#ifndef`，可用 `PERF_CFLAGS="-D..."` 覆盖。
- Makefile 新增 `PERF_CFLAGS ?= -O2` 并在 `perf-build` 中显式传给 `build-microbench.sh`，便于命令行 `-D` 调参。
- `scripts/build-microbench.sh` 对非 FP/NEON perf workload 自动追加 `-mgeneral-regs-only`，避免编译器在 FP 未使能前生成 Q/D 栈操作；FP 白名单：`fp_scalar fp_fp16 neon_vect`。
- `t_fp_scalar.c`：将任意浮点常量改为可用 `fmov` 立即数/受支持路径的值，移除 SP `fcmp` 自检。
- `t_fp_fp16.c`：改为纯内联汇编标量 H 吞吐循环，只使用 caller-saved 向量寄存器、H 算术、`fcvt H->S` 和 S 存储，避免 H 访存/GPR 传送/`fcmp`/`mov v.h`。
- `t_neon_vect.c`：向量常量改为内存常量并显式 LDR Q/D 加载，保留原 NEON 算术，移除向量 `fcmp` 自检。

## 复现命令

```sh
# 若需要重建 runner（本次已重建；cgroup <16GiB、VERILATOR_JOBS=1）
TMPDIR="$PWD/build/tmp" make VERILATOR_JOBS=1 microbench-build

# 单个 workload（默认 5M）
make perf PERF_NAME=alu_latency PERF_MAX_CYCLES=5000000

# 调参示例
make perf PERF_NAME=alu_latency \
  PERF_CFLAGS="-O2 -DPERF_ALU_ITERATIONS=80000" \
  PERF_MAX_CYCLES=5000000
```

## 建议最大 cycles 配置

- 默认 `PERF_MAX_CYCLES=5000000` 已足够覆盖当前全部 14 个 workload。
- 最高实测为 `mem_random` 3.91M；建议统一使用 5M 作为常规上限。
- 如需更大规模/更长运行，可设 `PERF_MAX_CYCLES=20000000` 或 `50000000`，但需同步用 `PERF_CFLAGS` 放大参数；当前默认参数不会用满 5M。

## 边界与已知限制

- 性能数据为软核性能代理数据，不是 A10/Fmax/架构签核。
- 未修改 RTL、未引入 SVE、未启动 Quartus。
- 当前 RTL/runner 的 FP 指令子集有限：`fmov` GPR<->FP、FP compare、FP16 半精度访存、向量 immediate/movi 等不建议在 perf workload 中使用；本任务已在 workload 侧规避。
- 若以后新增 FP/NEON perf workload，需要加入 `PERF_FP_NAMES` 白名单，否则会被 `-mgeneral-regs-only` 编译。
- runner 重建过程使用 `VERILATOR_JOBS=1` 和 cgroup MemoryMax<16GiB；构建产物在 worktree `build/`（不进入 Git）。
