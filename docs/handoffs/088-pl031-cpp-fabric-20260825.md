Verilator 链接的 C++ MMIO fabric，而没有新增 PL031 SystemVerilog。

```text
RTL core/MMU/cache
       ↓ M1-B（一拍 response）
lcvex_mmio_fabric.sv（DPI bridge）
       ↓

```

  和 PrimeCell ID；未知已分派地址记录 PA/读写/字节使能/数据并返回 fault；

  `0x09010000..0x0a020000` 分派给 fabric；PL061 的 MMIO3 在其前优先匹配，
  仍走原生 RTL；
- `rtl/lcvex_core.sv`、`lcvex_decode.sv`、`lcvex_mmu.sv`：MMIO4 放行且
  强制不可缓存；
- `Makefile`、Cocotb、microbench、所有 lockstep 构建均链接同一 C++ 源；
- `run_lockstep_step.sh`、`run_lockstep_resume.sh` 固定 QEMU：
  `-rtc base=2000-01-01T00:00:00,clock=vm`，与 `-icount shift=0` 的
  `1 ns/退休指令` 对齐；
- `hard_pl031` 已加入 M2-4b 与 Gate D 测试清单。

## checkpoint 语义

新链在原有 `ram/dev/arch/sys/timer/gic` 后增加第 12 列 `mmio.gz`，内容为
版本化 `LcvexMmioFabricState`。它保存 PL031 计数偏移、MR/LR、IM/IS、
alarm armed 状态和 bridge 虚拟时间；恢复时同时注入 C++ 状态和
`fabric.virt_ns_r`，不能只恢复其中之一。

- 新链：`run_lockstep_resume.sh` 自动读取第 12 列并传递 `--restore-mmio`；
- 旧 11 列链：继续兼容，C++ fabric 从 reset 开始，因此**不得**声称 C++ 外设
  状态联合恢复；
- `make checkpoint-mmio-smoke` 已实测：PL031 写入
  `LR=0x12345678` 后在 seq=9 保存，再恢复 QEMU VMState、DUT
  arch/sys/timer/gic/RAM 与 `.dev.mmio.gz`，后续 7 条逐指令锁步通过。

## 已验证

```sh
make sim-sv-mmio
make sim-cocotb-mmio
make sim-sv
make sim-cocotb-backpressure
make lockstep-build
bash sim/difftest/run_m2_4b.sh --only hard_pl031
make checkpoint-mmio-smoke
make compile
```

其中 `hard_pl031` 在 base 与 I+D L1+L2 配置均通过 24 条；PL031 C++ model
的 SystemVerilog 和 Cocotb 独立测试均通过。

Lite 平台路径也已实测：从
`build/tmp/linux-lite-6.6/long-ldpsw-v2-20260825/chain/diff-3199999`
恢复、使用 `build/difftest/linux-lite/{Image,initramfs,qemu-lite-fdt-raw.bin}`
额外逐指令锁步 200 条、100,000 条和 1,000,000 条均通过，已经跨过原先
`PA=0x09010fe0`（PL031 PID0=0x31）的 external DABT。

其中 1,000,000 条运行是在重建 kernel coordinator 前启动，生成的是兼容旧
11 列 checkpoint 链（保存于 `post-pl031-cpp-20260825`），只能作为执行路径
证据。随后已用重建后的 coordinator 创建独立 12 列链
`post-pl031-cpp-v2-20260825/chain`：seq=24999/49999 都带
`.dev.mmio.gz`，从 seq=49999 联合恢复后额外锁步 200 条通过。

## 当前状态与下一步

  RTC alarm 前，先实现并测试通用 GIC SPI 电平输入，避免暗中改变 IRQ 时序。
