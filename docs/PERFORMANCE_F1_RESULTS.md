# PE-F1c Fetch FIFO 同 SHA 成对性能复测

> 任务：T-20260830-043（PE-F1C）
> 测量源：`b2b0a96894596ade51e8409fc7b9d4eb566cfe63`
> 结论状态：**数据完整，但 F1a 架构等价护栏未通过；建议继续默认关闭 FIFO。**

本报告只描述 F0（`FETCH_FIFO_ENABLE=0`）与 F1a（`FETCH_FIFO_ENABLE=1`、2-entry FIFO）的
同 SHA Verilator 仿真复测。F1b 未实现、未测量，也没有创建或声称 `f1ab` 数据。
周期和内部事件是 Verilator 仿真代理，不是 A10/Fmax、FPGA 资源或架构签核。

| 项目 | 值 |

| measurement source SHA | `b2b0a96894596ade51e8409fc7b9d4eb566cfe63` |

| Verilator | 5.050 2026-07-01 rev conda-forge build 0 |

构建顺序先为每个 workload 生成一次镜像，再在所有配置上复用该镜像；同一 workload 的

`max_cycles` 和 measurement SHA 完全一致；仅 `FETCH_FIFO_ENABLE`（0/1）及其身份
`FIFO_VARIANT`（f0/f1a）按实验设计不同。

复现入口：

```sh
systemd-run --user --scope -p MemoryMax=15G -p MemorySwapMax=0 -- \

  python3 scripts/run_perf_matrix.py \
    --configs all --workloads all --max-cycles 5000000 \
    --out-dir build/f1c_matrix \
```

## 2. 总体结果与签核判定

| 项目 | 结果 |
| --- | ---: |
| 总 rows | 196 |
| `pass` | 177 |
| `timeout` | 19 |
| `fail` | 0 |
| status/returncode/retired/commit digest/memory digest 严格等价 pairs | 56/98 |
| `pass/pass` pairs | 88 |
| `pass/pass` 中 cycle 护栏通过 | 88/88 |
| `timeout/timeout` pairs | 9 |
| `timeout/pass` pairs | 1 |
| FIFO-on occupancy/peak 越界 | 0 |
| FIFO-on overflow | 0 |

架构摘要护栏要求 `status`、退出码、`retired_insn`、`commit_digest` 和
`memory_digest` 全部相同。实际只有 56/98 对满足；32 个 `pass/pass` 对的提交摘要
不一致，9 个 `timeout/timeout` 对的摘要也不一致，另有 `nocache_d1/mem_random`
为 `timeout/pass`。因此所有周期下降都只能称为“观测值”，不能作为 F1a 已安全且
架构等价的性能收益。

具体阻断模式如下：

- `nocache_d0`、`l1i_d0`、`l1id_l2_d0`、`fullcache_d1`、`fullcache_d2` 的内存/FP/NEON/
  sort 等 workload 出现 pass/pass 摘要或 retired 不一致；
- `nocache_d1/mem_seq` 为 timeout/timeout 但摘要不一致；
- `nocache_d1/mem_random` 为 f0 timeout、f1a pass，状态不一致；
- `nocache_d2` 的 5 个 timeout workload 均为 timeout/timeout，但提交摘要不一致。

这些差异没有被过滤、重跑成“通过”、修改 workload 或修改参考结果。建议保持
`FETCH_FIFO_ENABLE` 默认值 0，先定位 F1a 在数据/FP/向量/分支相关路径的提交序列
差异，再讨论性能签核；F1b 继续阻断。
