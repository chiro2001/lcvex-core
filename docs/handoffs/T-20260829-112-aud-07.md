## 结论

修复 `scripts/ci-difftest.sh` 与 `scripts/ci-nightly.sh` 前置步骤失败未纳入失败计数的问题：

- QEMU patch apply、QEMU build、plugin build、lockstep build、delay2 build、
  延迟镜像生成统一改走 `run_step`；任一前置步骤失败立即以非零退出（fail-fast），
  不再继续使用陈旧产物。
- 开始门禁前清理/隔离旧 plugin `.so`、Verilator lockstep 协调器二进制和 nightly
  delay2 定向镜像，避免非干净工作区中的旧 binary/image 掩盖真实失败。
- `VERILATOR_JOBS=1` 保证 CI 中重型 Verilator 串行构建；外层 cgroup 限制保持
  `<16GiB`（本次负向测试未启动重型构建，故未实际设置 cgroup）。
- `scripts/test_ci_failfast.sh` 提供 shell 级负向测试：在临时 sandbox 中用 stub
  注入各前置步骤失败，验证两个 CI 脚本均非零退出。

GitHub workflow 中独立的 QEMU apply/build/plugin step 本身会使 job 失败；本次
修复主要覆盖脚本被直接本地调用或后续在单一 step 中复用的路径，并补齐脚本内
前置步骤的显式失败处理。
