## 目标

关闭 EXT-05-003：发布模式 Gate D 在 baremetal-C 工具链缺失时不得打印“跳过”后仍全绿；
同时统一 `toolcheck.sh` 与 `build-baremetal.sh` 的实际 GCC/objcopy 检查前缀，并允许
`AARCH64_GCC` 覆盖时同步覆盖 objcopy。

## 修改文件

- `sim/difftest/run_gate_d.sh`
  - 默认（发布模式）把 `baremetal-C 工具链/镜像` 作为正式 step，缺失时进入 `fails`，
    Gate D 最终非零失败。
  - 新增 `--skip-baremetal`：显式非发布/开发模式，打印 SKIP 且不计失败。
  - 新增 `--check-baremetal`：只执行 baremetal 工具链/镜像检查，不触碰重型
    Verilator/回归，用于隔离 PATH 快速负测。
- `scripts/build-baremetal.sh`
  - 不再硬编码 `aarch64-linux-gnu-objcopy`。
  - `AARCH64_GCC` 覆盖时按同前缀推导 objcopy；可用 `AARCH64_OBJCOPY` 显式覆盖。
  - GCC 或 objcopy 任一缺失均以退出码 2 失败。
- `scripts/toolcheck.sh`
  - 不再检查错误的 `aarch64-none-elf-gcc`，改查与 build 一致的
    `aarch64-linux-gnu-gcc` / `aarch64-linux-gnu-objcopy`。
  - 与 build 脚本使用相同 `AARCH64_GCC` / `AARCH64_OBJCOPY` 覆盖逻辑。
  - 缺失仍为 WARN（避免非 Gate 开发被硬断），但消息明确“Gate D 发布模式需要”。

## 验证

### 正向
- `bash scripts/build-baremetal.sh` → rc=0，生成 `build/difftest/bm_c.bin`。
- `bash sim/difftest/run_gate_d.sh --check-baremetal` → rc=0。
- `AARCH64_GCC=/usr/bin/aarch64-linux-gnu-gcc bash scripts/build-baremetal.sh` → rc=0，
  证明 GCC 覆盖可同步推导同前缀 objcopy。
- `bash scripts/toolcheck.sh` → aarch64 gcc/objcopy 均 `OK`，qemu/verilator/cocotb 等正常。

### 负测（隔离 PATH，缺交叉工具链）
- 使用仅含 `bash/mkdir/dirname/stat/env` 的隔离 PATH，不含
  `aarch64-linux-gnu-gcc` / `aarch64-linux-gnu-objcopy`。
- `env PATH=<isolated> bash scripts/build-baremetal.sh` → **rc=2**：
  `错误：找不到交叉工具链 aarch64-linux-gnu-gcc ...`
- `env PATH=<isolated> bash sim/difftest/run_gate_d.sh --check-baremetal` → **rc=1**：
  `FAIL: baremetal-C 工具链/镜像不可用（发布模式不得跳过）`
- 因此发布模式 Gate D 的 baremetal-C 前置缺失不会再假绿。
