## 实现摘要

将 `FETCH_FIFO_ENABLE`、`FETCH_FIFO_DEPTH`、`FETCH_EPOCH_W` 从
`lcvex_core` 参数向系统/多核/SoC/FPGA 顶层传播，并把默认
`FETCH_FIFO_ENABLE` 从 0 改为 1（`FETCH_FIFO_DEPTH=2`、`FETCH_EPOCH_W=8` 不变）。

`rtl/lcvex_core.sv` 未改动，核心默认仍为 0；默认-on 由外围层次传递实现。

传播路径与默认值：

| 层次 | 新增/变化 |
| --- | --- |
| `rtl/lcvex_core_wrap.sv` | 新增三个参数，默认 `1/2/8`，透传给内部 `lcvex_core` |
| `rtl/lcvex_cluster_top.sv` | 新增三个参数，默认 `1/2/8`，透传给每个 `lcvex_core_wrap` |
| `rtl/lcvex_catapult_soc_top.sv` | 新增三个参数，默认 `1/2/8`，透传给内部 `lcvex_core` |
| `fpga/catapult_a10/rtl/lcvex_catapult_a10_top.sv` | 新增三个参数，默认 `1/2/8`，透传给 `lcvex_catapult_soc_top`；任务包中写为 `rtl/lcvex_catapult_a10_top.sv`，仓库实际路径为 `fpga/catapult_a10/rtl/` |
| `tb/sv/lcvex_soc_tb.sv` | 已有参数，默认 `FETCH_FIFO_ENABLE` 改为 `1` |
| `Makefile` | `PERF_FETCH_FIFO_ENABLE ?= 1`；`make compile` 增加 `-Wno-UNUSEDSIGNAL` 以消除 F1a `raw_control_flow` 既有 UNUSEDSIGNAL 警告 |

显式 F0 关闭仍可用：任何层次传入 `FETCH_FIFO_ENABLE=0`，或性能 runner 使用
`PERF_FETCH_FIFO_ENABLE=0`，均保留原 F0 路径。

## 边界与风险

- 未改动 `lcvex_core.sv` 的功能语义、提交协议、FIFO/epoch 或架构状态。
- 未运行 Gate D、全量微基准矩阵、QEMU lockstep、Linux 长跑、Quartus full flow/板测。
- 默认开启后，未显式传 `FETCH_FIFO_ENABLE=0` 的既有 `lcvex_soc_tb` 使用方会走 F1a；这是本任务“默认-on”的预期变更，F0 复测需显式覆盖。
- `make compile` 的 `-Wno-UNUSEDSIGNAL` 仅影响 lint warning 级别，不改变 RTL/断言。
