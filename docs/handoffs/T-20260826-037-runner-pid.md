## 根因

T-036 Gate D 并行运行中，多个 QEMU 已经失去协调器仍存活，PPID=1，资源
规划器持续报告 `cpu_free=0`。原因是 T-032 的 `run_pinned` 函数在后台
执行，`$!` 是 shell 包装进程而不是 QEMU；runner 发送 TERM 后 QEMU 未被
回收。

## 修复

`run_pinned` 的 pin/no-pin 两条路径均使用 `exec`，使后台 PID 直接成为
`taskset`/目标 coordinator 或 QEMU 进程。原有 `PLUGIN`、`COORD_PIN`、
`QEMU_PIN` 参数保持不变。

## 验证

- `bash -n` 与 `git diff --check`：通过。
- 100,000 条 step smoke（协调器/QEMU 物理核 10/11）：通过。
- smoke 结束后未发现 T-037 worktree 的孤儿 QEMU/coordinator。

## 后续

合入后从当前候选重新执行 T-036 Gate D；此前 T-036 的日志保留为
`infra-fail/process-leak`，不计入 Gate D 结果。
