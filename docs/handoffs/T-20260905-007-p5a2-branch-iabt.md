## 结论

已恢复 FIFO-on 下 branch-target instruction-abort 的精确合并提交。`p5a2_fetch`
原先在 seq=16 的 `BR X3`（`0x4000000c -> 0x50000000`）先正常提交，QEMU 则将
同一条 BR 合并为 EL1 IABT；修复后 branch 会保持在 MEM/WB，直到目标取指结果
（正常 entry 或 matching fault）settled，再由既有 `fetch_merge_wb` 生成一次提交。

针对 integrator review 的 rework 还补强了 maintenance owner：已接受的 IC
响应由独立 `maint_imem_rsp_pending` metadata 持有，跨 younger flush、状态机回到
`MS_IDLE` 或 older fetch-wait 仍排空到 maintenance，而不会被普通 fetch 接收。

## 根因与修复

原 `fetch_walk` 只冻结流水级更新，`commit_fire` 仍直接由 `memwb_valid`、
`memwb_committed_r` 和 `commit_ready` 决定。目标 MMU walk 尚未完成时，older BR
因此先退休；后到的 fault 只能进入 FIFO，失去可绑定的 older MEM/WB。

`rtl/lcvex_core.sv` 新增 `memwb_fetch_target_settled` 与 `memwb_fetch_wait`：

- FIFO-on 只接受 current-epoch matching FIFO entry 或 matching `fetch_faulted`；
  IF/ID、ID/EX、EX/MEM 中已交付的 matching PC 也视为 settled。
- FIFO-off 只对明确 matching 的 legacy fetch context 等待实际 IMEM data/fault，
  并在 fetch translation request acceptance 时锁存 `fetch_pc_r`。
- `memwb_fetch_wait` 并入 `stall_wb`，因此 MEM/WB、EX/MEM、ID/EX 和 FIFO pop
  保持原子；`commit_fire` 在结果未 settled 时为 0。
- older entry 等待期间抑制 younger `sys_fetch_redirect`、maintenance IMEM/DCZVA
  request、TLBI pulse 和 maintenance FSM 启动，避免 younger 边界清掉 older fault
  context；已接受的 maintenance response 仅允许通过登记的 response owner 排空。
- `maint_imem_req_selected` 绑定 request owner，`maint_imem_rsp_pending` 绑定
  accepted-but-not-consumed response；request/response、状态保持和 sys-commit
  前置条件均有 core SVA。
- 未修改公共 commit packet、QEMU/plugin、MMU、FP/muldiv 或 reference。

新增 F1a SVA 要求等待期间无 `commit_fire`，以及正常提交必须有 settled target。
